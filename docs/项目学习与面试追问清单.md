## 第 1 部分：模块学习顺序（每块 5 分钟建立"一句话讲法"）

### 0. 先花 10 分钟跑一遍，建立身体记忆
```powershell

```

### 1. 编排层：src/graph/workflow.py
- **一句话讲法**：语言都不如"六个节点 + 一个判断"，全流程用 LangGraph 的有向图跑。
- 必须能指出的点：`_build_graph()` 里 `collect → monitor → analyze → validate → correlate → report`
  六条边 + 一条条件边（correlate 后根据 `generate_report` 决定进 report 还是直接结束）。
- 面试官大概率问：为什么用 LangGraph 不用普通函数调用？
  → 答：真实有状态的编排（条件边、可观测节点日志、可显式建模），且做了 `HAS_LANGGRAPH` 守卫，
  没装也能线性回退。

### 2. 采集层：src/agents/collector.py + src/sources/
- **一句话讲法**：Collector 并发调多个数据源适配器，哈希去重后落 raw 表。
- 适配器清单（看 src/sources/ 目录就能数出来）：RSS、API(NVD/GitHub)、演示源、本地数据集、合规暗网源。
- 追问点：如何防重复？→ `content_hash` 唯一索引，重复返回 False 跳过。

### 3. 分析层：src/agents/analyzer.py + src/llm/
- **一句话讲法**：Analyzer 把原始文本交给 LLM（演示=确定性 DemoLLM，真实=大模型），
  抽取出威胁类型/IoC/置信度，构造成结构化 ThreatIntelligence。
- 双模式接口要点：`DemoLLM` 与真实 `LLMClient` 共用 `invoke()` 接口 → 所以演示/真实可一键切换。
- 追问点：真实模式用什么模型？→ 百炼兼容 OpenAI 协议，模型名见 `.env LLM_MODEL`。

### 4. 评审层：src/agents/reviewer.py（本阶段学习重点，最显"多智能体"）
- **一句话讲法**：每条分析结果交给**独立** Reviewer 挑错，Coordinator 依据可修复的反馈真实去改，
  然后复评、记录（rounds / approved / 置信度前后）。
- 证据点（面试必讲）：`docs/面试准备.md` 里"对抗评审不是摆设"——部分争议情报被校准（0.89→0.35）。
- 追问点：Reviewer 怎么实现"独立"？→ 独立规则 + 可选 LLM 双模式；与 Analyzer 是分离的两个类。

### 5. 校验层：src/agents/validator.py
- **一句话讲法**：Validator 用"置信度阈值 + IoC 数量 + 语义关键字"三维判断 is_valid，过线才入库有效。
- 追问点：为什么演示模式不套英文预过滤？→ 演示样本是中文，英文关键字过滤会误杀伤（代码里有注释）。

### 6. 关联层：src/agents/correlator.py（本阶段必学，你简历里写到了）
- **一句话讲法**：按共享 IoC（IP/域名/URL/Hash）union-find 聚类，独立来源数 ≥ 2 判 corroborated
  并把置信度 +0.03（封顶 1.0）。
- 证据点：标准数据集上印证 1 起 CVE 事件（2 来源、置信度 1.00）——这一条对应简历"跨源印证"。

### 7. 评估体系：src/evaluation/（测开/AI 测试岗核心卖点，重点中的重点）
- `ab_tester.py`：在固定 benchmark 上对比提示词 v1.0→v1.3，演示模式用确定性 mock 评分。
- `regression.py`：回归护栏，待部署版本低于基线（v1.2）即拦截。
- `runtime.py`：把胜出版本写 `data/runtime_prompt.json`，Analyzer 运行时读取——"评估结论真的进生产"。
- 追问点：为什么演示模式评分是确定的？→ mock 用稳定种子（SHA-256），保证可复现。

### 8. 存储层：src/storage/db.py + src/models/
- **一句话讲法**：SQLAlchemy ORM，五张以上业务表（raw / intel / reviews / events / domain_metrics），
  关键 `expire_on_commit=False` 兼容面板读取。
- 追问点：如何迁移？→ `create_tables` 幂等建表；MVP 阶段轻量。

### 9. Dashboard：dashboard/app.py
- **一句话讲法**：Streamlit 五页（总览 / 专题监测 / 情报列表 / A/B 评估 / 运行工作流），
  演示模式下零额度可跑完整链路。
- 按岗位调重点：投 AI 测试 → 打开"A/B 评估"页；投测开 → 打开"运行工作流"页展示 40 用例与评审。

### 10. 合规暗网：src/sources/dark_web_source.py
- **一句话讲法**：白名单 + 显式 SOCKS5 代理 + 关键词过滤 + 默认关闭，只抓已知地址、绝不自动发现。
- 备一个诚实口径：上线靠 fail-closed（没代理直接拒绝）+ 全量审计日志。

## 第 3 部分：验证暗网必做（你欠自己的一次真跑）

**触发条件**：梯子稳定 + Tor Browser 能连接。
```powershell
# 1) 代理连通性（不需要真地址，先确认端口通）
D:\Anaconda\python.exe scripts\verify_darkweb_proxy.py

# 2) 若第 1 步 [OK]，把 settings.yaml 里 darkweb.enabled 改 true、port 填 9150、
#    whitelist 换上你自己核实过的 .onion 地址，再跑一次同脚本看 [RESULT]。

# 3) 跑完整链路（含真实 LLM 分析暗网命中页）
D:\Anaconda\python.exe scripts\run_pipeline.py --limit 20
```
跑通后回来更新 `docs/开发记录.md` + `docs/面试准备.md` 的"真实验证"章节，并给自己加一行 green check。

### 若测试失败，按这个顺序查
1. `netstat -ano | findstr 9150` → 确认端口在听（Tor Browser 要开着）
2. 代理类型：是 `socks5h`（域名也走代理），不要写成 `socks5`
3. whitelist 地址必须 `.onion`/`.i2p` 且是你验证过可访问的；抓不到换一个已知可达源
4. 关键词过滤太严 → 页面不匹配直接丢弃（这是设计行为，不是 bug）
