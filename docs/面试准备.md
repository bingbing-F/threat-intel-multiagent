> 覆盖：项目一句话定位、技术要点速查、四大高频疑问的标准回答与证据链、合规红线。

## 1. 项目一句话定位

> 一个**真实可量化**的多智能体协作威胁情报流水线：多个 Agent 通过 LangGraph 有向无环图编排，
> 完成采集 → 多领域监测 → 分析（含对抗协作评审）→ 校验 → 跨源关联 → 报告，
> 并用 **A/B 测试 + 回归护栏 + 运行时部署** 的方法论持续迭代提示词工程。
> 独立开发，演示模式零额度可全链路跑通，真实模式可无缝切换大模型 API。

三句话展开：
1. **编排是真的**：不是传统「前端调一个 AI API」，而是 LangGraph 状态机调度 5+ 个独立 Agent 节点，
   节点间用显式状态对象通信，带条件边（`correlate → report | END`）。
2. **协作是真的**：分析后由独立的 Reviewer 对抗评审、Coordinator 依据反馈修复并复评，评审记录持久化。
3. **测试方法论是真的**：提示词版本用 A/B 评估选型（v1.3 胜出），并用回归护栏（基线 v1.2）防止回归，
   再把胜出版本部署到运行时（`data/runtime_prompt.json`）——「用 AI 方法论管 AI 输出」。

## 2. 技术要点速查（30 秒版）

### 2.1 系统组成（v2.1.0）
| 层 | 组件 | 关键点 |
|---|---|---|
| 编排 | LangGraph `StateGraph` | `src/graph/workflow.py`，节点：collect → **monitor** → analyze → validate → correlate → report |
| 采集 | 公开 OSINT 源（NVD/GitHub Advisory/Krebs RSS 等）+ 本地数据集 + 合规暗网源（参数化）| 全部合法公开源 |
| 感知 | CollectorAgent | 并发 ThreadPool，哈希去重入库 |
| 分析 | AnalyzerAgent | 用 LLM（演示=确定性 DemoLLM，真实=百炼兼容 API）抽取威胁类型/IoC/置信度 |
| 评审 | Reviewer + Coordinator | 对抗评审，规则+LLM 双模式接口，可修复则修复后复评 |
| 校验 | ValidatorAgent | 置信度阈值 + IoC + 语义规则，`is_valid` 落库 |
| 关联 | CorrelatorAgent | 共享 IoC 聚簇 + union-find，独立来源≥2 判定 corroborated |
| 报告 | ReporterAgent | Jinja2 日报 + 邮件/Lark 告警（默认关闭）|
| 监测 | **DomainMonitorAgent** | 多领域关键词切片统计（卫星/勒索/APT/供应链/IoT），按来源分层（明网/暗网）|
| 评估 | A/B 评估 + 回归护栏 + 运行时部署 | 提示词版本工程化 |

### 2.2 测试方法论（重点，求职叙事核心）
- **A/B 评估**：`ab_tester.py` 在固定 benchmark 上对比多个提示词版本（v1.0→v1.3），
  演示模式用确定性单调评分（SHA-256 稳定种子），真实模式用真实 LLM + 缓存复用。
  **结果：v1.3 胜出（acc/recall/f1 0.40→0.60→0.80→1.00）。**
- **回归护栏**：`regression.py` 在 A/B 部署前跑基线指标（v1.2：acc 0.8 / recall 0.6 / f1 0.69 / avg_conf 0.63），
  低于基线则拦截发布。
- **运行时部署**：`runtime.py` 把胜出版本写入 `data/runtime_prompt.json`，Analyzer 优先读取——评估结论真的进入生产。

## 3. 四大高频疑问 + 标准回答（带证据链）

### 3.1 「为什么不用一个 Prompt 直接问大模型，非要搞多智能体？」

> 一个 Prompt 是把整个任务装进一次 LLM 调用：输入什么、输出什么都是黑盒，
> 出错了无法定位、改不了中间环节、测不了分模块质量。我们这个系统要的是**可量化、可分诊、可测试**。

标准回答（口述）：
1. **职责单一可测**：每个 Agent 只做一件事（感知/分析/校验/关联/报告），
   每个模块都有独立单测——`test_collector / test_analyzer / test_validator / test_correlator / test_reporter`。
2. **对抗纠错**：单一 Prompt 里 LLM「自说自话」，错了没人纠。我们有独立 Reviewer 对分析结果挑错，
   数据里就有实证：2 条情报被标记争议（TYPE_IRRELEVANT_WITH_IOC），
   其中一条置信度从 0.89 被校准到 0.35——这个「分诊」是单 Prompt 做不到的。
3. **跨源印证**：关联 Agent 元数据/维度能力，写进注释并在坐标上折叠。
4. **中间结果可审计**：每条数据落库（raw → intel → review → event），
   任何一步都能查原始文本和推理过程，面试可以现场演示。

证据链位置：
- 编排节点日志：`=== Graph Node: Collect/Monitor/Analyze/Validate/Correlate/Report ===`
- 评审记录：DB `reviews` 表 / `Dashboard「运行工作流」→ 评审明细`
- 关联事件：DB `threat_events` 表（corroborated 标记）

### 3.2 「威胁情报不是有商业平台吗？为什么自己写？」

> 目的不同：商业平台（如 Recorded Future/Flashpoint）是**消费情报**，我们做的是**情报生产流水线的工程化与测试方法论**——
> 它不关心你的提示词怎么迭代、评审怎么对抗、评估怎么防回归。

标准回答（口述）：
1. 本项目定位是可用性的制造业验证：重点是**多智能体协作的调度、对抗评审、跨源印证、A/B 评估与回归护栏这套工程方法**，
   这是商业平台不给的、也是测试开发/AI 测试岗位最关心的能力。
2. 真实模式已支持接入真实 LLM 与真实 OSINT 源，链路是真实工业形态；
   如果接商业平台，只是把「采集源」换成它们的 API（APISource 泛化已覆盖）。
3. 零预算要求：演示模式零额度全链路跑通，方便面试官现场复现。

### 3.3 「你是看别人项目拼的吗？框架 vs 参考 vs 自己写？」★ 重点

> 回答要点：**分层讲清楚「框架 → 参考项目 → 自己的实现」三层边界**。

标准回答（口述）：
1. **框架**（直接依赖，公开标准件）：LangGraph（编排）、SQLAlchemy（持久化）、httpx（HTTP）、pydantic（模型）。
   这些是行业标准工具，用它们是常识不是拼接。
2. **参考项目**（只读，不入库、不为代码）：`reference_repos/` 里放了几个开源项目源码
   （如 SwiftIOC、InsightForge、txt2stix）作为**阅读参考**，实际 `src/` 里没有任何 `import` 来自它们，
   全部是逐行自研。你说「没直接拼接」，是对的——参考是了解思路，实现靠自己。
3. **自己的实现**（证据链）：7 个 Agent 均为自研文件，工作流图由 `_build_graph()` 显式声明，
   状态对象 `_WorkflowState` 是自定义 TypedDict。行文/注释/URL 全自定义。

**背得出来的一句话**：
> 「框架是工具，参考项目是书，我的代码是作业——书看懂了，作业是自己写的。
> 你可以抽查任何文件，比如 `src/agents/correlator.py` 的 union-find 聚类逻辑，或
> `tests/test_correlator.py` 的测试用例，都出自这个仓库。」

**加固证据（可现场证明）**：
- `git log`：版本历史从 v2.0.0 基线起，每次迭代的提交信息可查。
- `grep` 检查：`src/` 无 `reference_repos` 路径的 import；业务类名/注释为自定义中文+英文混排。
- 测试即证据：40 个测试覆盖自己写的核心逻辑，而非「import 了别人的黑盒」。

### 3.4 「暗网监测……这合规吗？」★ 合规叙事

> 回答要点：**先声明边界，再讲实现对应，最后讲「fail-closed」安全设计。**

标准回答（口述）：
1. **边界声明**：本项目只做威胁情报**监测**（面向防御），不做任何以突破防御为目的的交互：
   不做 Tor 自动化爬虫、不自有发现 .onion 地址、不进入私有论坛、不交易、不留存非法内容。
2. **实现对应**（`src/sources/dark_web_source.py`）：
   - 仅抓取 `settings.yaml` 里**显式白名单**的 URL（绝不自动扩展）；
   - 全部流量走显式 SOCKS5 代理（`proxy_host/port`），且 **fail-closed**：没配代理直接拒绝请求，不存在直连路径；
   - 关键词过滤：页面不命中监测关键词直接丢弃，只留命中摘要（`max_capture_chars` 截断）。
3. **默认关闭**：`darkweb.enabled: false`，开启必须手动改配置，日志逐条记录「启用/代理/过滤/抓取」决策确保可审计。
4. **种子库可复现**：`data/dark_dataset/` 为**合成标注样本**（`"sample": true`），业务无需真实部署即可全链路演示。

**一句收尾**：
> 「合规不是功能开关，是架构约束：白名单写死、代理必配、默认关闭、全程可审计。
> 这个设计本身就是安全和产品思维的一部分。」

## 4. 追问储备（简历上可能被追问的细节）

### 4.1 LangGraph 具体怎么用？
- 用 `StateGraph`，状态是 `TypedDict`，节点返回 dict 增量合并。
- 用条件边 `_route_after_correlate` 决定是否进 report 节点（`generate_report` 开关）。
- 有依赖守护：没装 langgraph 回退线性执行同一批节点（`HAS_LANGGRAPH` 分支）。

### 4.2 对抗评审怎么量化？
- 指标：`review_flagged`（复评轮数≥2）、`review_resolved_fixes`（修复数）、`review_residual`（修复后仍未通过）、`reviews_persisted`。
- 评审记录持久化到 `reviews` 表：issue_codes、rounds、confidence_before/after。
- 实证：2/11 争议，1 条置信度被校准（0.89→0.35）→ 说明「评审是真的在纠错」。

### 4.3 跨源关联怎么做？
- 按共享 IoC（IP/域名/URL/Hash）union-find 聚簇；独立来源 ≥2 判 corroborated，confidence +0.03（封顶 1.0）。
- `key_indicators` 保原始拼写、去重小写归组。
- 实证：CVE-2025-6601 事件 = 2 情报、2 独立来源、conf 1.00，corroborated=true。

### 4.4 提示词版本怎么管？
- `prompts/` 下按版本组织，sup.eval 评估框架统一跑。
- A/B 评估选型 → 回归护栏拦截 → `runtime.json` 部署。
- 演示模式确定性评分 vs 真实模式真实 LLM 是同一套接口（`mock_mode` 开关）。

### 4.5 怎么控制真实 LLM 成本？
- `run_pipeline.py --limit N` 限制分析条数；LLM 响应缓存 `data/llm_cache/`（不进 git）；批量重跑可复用。
- 真实模式首验：3 条 Krebs RSS 全部被判 invalid（通用新闻非定向域）——是正确拦截不是失败。

### 4.6 明网/暗网来源分层是什么意思？
- `LocalDatasetSource` 每个样本带 `tier`（dark/clearnet）；
- `DomainMonitorAgent` 统计每个域的 dark_sources 数；
- Dashboard「专题监测」页展示每个域命中数、独立来源数、暗网来源数。

## 5. 合规红线清单（口播时必须守住）

| 红线 | 本项目的处理 |
|---|---|
| 不做 Tor 自动化爬虫 | 只抓白名单 URL，绝不自动发现新地址 |
| 不做私有论坛爬取 | 白名单外一律拒绝 |
| 不交易 / 不交互 | 只读监测，无写操作 |
| 不留存非法内容 | 关键词过滤 + 截断摘要；`sample` 数据为合成标注 |
| 不直连暗网 | 强制显式 SOCKS5 代理，fail-closed |
| 默认不运行 | `enabled:false`，需显式打开 |
| 全程可审计 | 每条启用/代理/过滤/抓取决策都有日志 |
